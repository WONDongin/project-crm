# 관리자 사용자 검색·필터·페이징

## API

`GET /admin/users?keyword=&roles=&status=&page=0&size=10`

로그인한 활성 관리자만 조회한다. 기존 `/admin/users` 응답의 `data` 배열을 페이지 객체로 변경했으며, 프론트 API 호출부와 목록 화면도 함께 변경했다.

| 파라미터 | 기준 |
| --- | --- |
| keyword | 이름 또는 이메일 부분 일치(OR), 앞뒤 공백 제거, 대소문자 구분 없음. 최대 100자. `%`, `_`, `!`는 문자 그대로 검색 |
| roles | 역할 정확히 일치, 빈 값은 전체. 최대 20자 |
| status | 상태 정확히 일치, 빈 값은 전체. 최대 20자 |
| page | 0부터 시작. 기본값 0 |
| size | 1~100. 기본값 10. 화면은 10개씩 표시 |

검색어 조건과 역할·상태 조건은 AND로 적용한다. 존재하지 않는 코드 조건은 빈 결과를 반환한다.
음수 페이지, 크기 범위 초과, JPA offset 한계 초과 및 검색 조건 길이 초과는 400으로 처리한다.

```json
{
  "success": true,
  "data": {
    "content": [],
    "number": 0,
    "size": 10,
    "totalElements": 0,
    "totalPages": 0
  }
}
```

사용자 ID 내림차순(최신 등록 순)으로 조회한다. 현재 페이지 사용자들의 담당 고객 수만 별도 그룹 집계로 조회하며, 담당 고객이 없으면 0으로 표시한다. 비밀번호 및 인증 버전은 응답에 포함하지 않는다. 범위를 벗어난 페이지는 전체 검색 건수와 빈 content를 반환한다.

## 화면

- `/admin/users` 목록 상단에서 이름·이메일 검색, 역할·상태 필터를 제공한다.
- 검색 버튼 또는 Enter로 조건을 적용하고 첫 페이지부터 조회한다. 초기화는 모든 조건을 지운다.
- 이전·다음 버튼으로 이동하고 검색 결과 수·현재 페이지·전체 페이지를 표시한다.
- 계정 생성·수정·비밀번호 초기화 및 본인 계정 보호 동작을 유지한다.
- 저장 후 현재 검색 조건으로 다시 조회한다. 생성 후에는 첫 페이지로 이동한다. 생성한 계정이 현재 검색 조건과 다르면 목록에 나타나지 않을 수 있다.
- 수정으로 필터 결과 수가 줄어 현재 페이지가 사라지면 마지막 유효 페이지를 다시 조회한다.
- 조회 중 중복 조작을 막고 이전 조회를 취소한다. 실패 시 검색 입력을 유지하며 재조회할 수 있다.
- 조건에 맞는 계정이 없는 상태와 계정이 전혀 없는 상태를 구분한다.
- A안 스타일, 반응형 검색 폼 및 표 내부 가로 스크롤을 유지한다.

## 확인 항목

- 전체·부분 검색, 이름/이메일 OR와 역할/상태 AND, 이메일 대소문자, 검색 공백, 특수문자 검색.
- 10개 단위 서버 페이징과 정렬, 현재 페이지의 담당 고객 수, 빈 결과와 범위 밖 페이지.
- 역할·상태 수정 후 필터 결과 재계산, 페이지·크기·길이 검증, 활성 관리자 권한.
- 프론트 프로덕션 빌드·TypeScript 및 변경 파일 ESLint.
- 실제 MySQL 브라우저 확인: 11개 이상 계정으로 검색·초기화·페이지 이동, 마지막 페이지 계정 수정 시 페이지 보정, 기존 모달 동작을 확인한다.

- JDK 17 / Gradle 8.14.4 전체 백엔드 테스트 104개 통과(실패·오류·건너뜀 0).
- Next.js 프로덕션 빌드·TypeScript 검사·변경 파일 ESLint 통과.
- 브라우저 검증은 실행 환경의 Chromium 시작 제한으로 미완료. 실제 MySQL을 연결한 화면 검증은 위 확인 항목에 따라 진행한다.

# 상담 기록 조회

상담사 고객 상세 화면 하단에서 신청 접수 기록과 상담 이력을 함께 조회한다.

## API

`GET /consultant/customers/{customerId}/activities?page=0`

- `page`: 0부터 시작하는 페이지 번호. 생략하면 0, 음수·숫자가 아닌 값은 400.
- 서버에서 페이지 크기를 5로 고정한다. `size`, `sort`, `counselorId` 요청값으로 변경할 수 없다.
- 정렬: `createdAt DESC, activityId DESC`. 작성일이 같아도 순서를 고정한다.
- 인증된 상담사의 현재 담당 고객만 조회한다. 타 담당·미배정·없는 고객은 403, 로그인 사용자가 삭제되었으면 401.
- 고객 담당자가 바뀌면 이전 담당자는 접근할 수 없고 현재 담당자는 이전 상담사의 기록까지 조회할 수 있다.
- `SYSTEM` 신청 접수 기록도 포함한다. 조회로 신청 원본, 고객 상태, 최근 상담일을 변경하지 않는다.

응답은 기존 `ApiResponse`를 사용한다. `data`의 필드는 다음과 같다.

| 필드 | 의미 |
| --- | --- |
| `content` | 현재 페이지 기록 배열 |
| `number` | 현재 페이지 번호 (0부터 시작) |
| `size` | 5 |
| `totalElements` | 해당 고객의 전체 기록 수 |
| `totalPages` | 전체 페이지 수 |

기록에는 `activityId`, `createdBy`, `counselorName`, `consultType`, `activityResult`, `preferredTime`, `content`, `nextAction`, `createdAt`을 반환한다. 상담사 엔티티나 비밀번호 등 계정 정보는 반환하지 않는다. 작성자 관계를 함께 조회해 행마다 추가 조회하지 않으며, DB에서 페이지를 나눈다.

기록이 없거나 마지막 페이지를 넘으면 `content`는 빈 배열이다. 기록이 없을 때 `totalElements`와 `totalPages`는 0이다.

## 화면

- 신청 접수 / 상담 이력을 구분하고 작성자·작성일·유형·결과·내용·다음 액션을 표시한다.
- 신청 접수에는 희망 상담 시간도 표시한다. 줄바꿈은 유지하고 긴 내용은 화면 안에서 줄바꿈한다.
- 이전·다음 버튼은 서버에 해당 페이지를 요청한다. 첫 페이지의 이전, 마지막 페이지의 다음은 비활성화한다.
- 로딩, 빈 목록, 오류 후 재시도를 제공한다. 페이지 이동 중 기존 요청을 취소해 늦은 응답이 화면을 덮어쓰지 않게 한다.
- 페이지 조회에서 403/404를 받으면 기존 고객 정보와 기록을 화면에서 지운다.

## 검증

- 백엔드: `./gradlew test` — 기존 11개 및 신규 6개, 총 17개 통과. H2 기반 통합·MockMvc 테스트.
- 신규 검증: 12건의 5/5/2 페이지 분할, 날짜와 동일 날짜의 ID 정렬, 다른 고객 제외, 빈 목록·범위 밖 페이지, 이전 담당자 기록 포함, 담당자 변경·미배정·타 담당·미존재 접근 차단, 로그인 사용자 ID 사용, 페이지 입력 오류, 고정 페이지 크기.
- 프론트: `npx tsc --noEmit`, 변경 파일 ESLint, `npm run build` 통과. 이 실행 환경에서는 빌드에 `NEXT_TURBOPACK_EXPERIMENTAL_USE_SYSTEM_TLS_CERTS=1`을 사용했다.
- 브라우저: API 모의 응답으로 5/5/2건 페이지 이동·경계 버튼·빈 목록·로딩·오류 후 재시도·403에서 고객/기록 숨김을 확인했다. 1440/768/390px에서 긴 한글 본문을 포함해 가로 넘침이 없음을 확인했다.
- 실제 MySQL 및 운영 로그인 연결 확인은 별도 진행한다.

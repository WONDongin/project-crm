# 고객 검색·서버 페이징 및 상담사 대시보드

## 변경된 API 계약

관리자 `GET /admin/customers`와 상담사 `GET /consultant/customers`의 `data`는 배열에서 아래 페이지 객체로 변경된다. 프론트와 백엔드를 함께 반영한다.

```json
{
  "success": true,
  "data": {
    "content": [],
    "number": 0,
    "size": 10,
    "totalElements": 0,
    "totalPages": 0
  }
}
```

| 파라미터 | 기본값 | 동작 |
| --- | --- | --- |
| keyword | 빈 문자열 | 이름 또는 연락처 부분 검색. 이름의 `%`, `_`, `\`는 문자 그대로 비교 |
| status | 빈 문자열 | 고객 상태 일치 |
| interestCourse | 빈 문자열 | 관심 과정 일치 |
| counselorId | 없음 | 관리자 담당자 필터. 상담사는 본인 이외 번호를 지정하면 403 |
| unassigned | false | 관리자 미배정 고객 필터. counselorId와 동시 사용하면 400, 상담사 사용은 403 |
| page | 0 | 0부터 시작하는 페이지 |
| size | 10 | 1~100 허용. 화면은 10명 고정 |

조건은 AND로 조합한다. 최신 고객 ID 내림차순으로 정렬하며, 빈 검색 조건은 적용하지 않는다. 검색어는 최대 100자, 상태와 과정은 각각 최대 30자다. 잘못된 페이지·크기·담당자 값은 400으로 거절한다.

숫자와 연락처 구분자로 구성된 검색어는 구분자를 제거해 비교한다. 기존 전화번호의 하이픈·공백·괄호·점·더하기도 조회 시 제거하여 비교하며 저장값은 바꾸지 않는다. 응답 연락처의 기존 마스킹을 유지한다.

상담사 범위는 서버에서 로그인 사용자로 강제한다. 목록 전체를 브라우저에서 필터링하지 않고 DB 조회와 count에 같은 조건을 적용한다. 담당자 표시에는 EntityGraph로 to-one 관계를 함께 조회한다. 조회 필터는 기존 비활성 코드의 고객도 찾을 수 있도록 코드 문자열을 허용하며, 저장 시 기존 활성 코드 검증은 유지한다.

## 화면 동작

- 관리자: 검색·상태·관심 과정·담당자/미배정 필터, 배정·변경·해제.
- 상담사: 본인 담당 범위에서 검색·상태·관심 과정 필터, 기존 상태·태그 수정과 상담 기록 링크 유지.
- 검색/초기화 시 첫 페이지로 이동한다. 이전·다음 이동 시 적용한 조건을 유지한다.
- 저장 후 같은 조건으로 재조회한다. 필터 조건에서 빠진 고객은 사라지고 마지막 페이지가 줄면 유효한 마지막 페이지로 이동한다.
- 저장하지 않은 수정값이 있으면 검색·초기화·페이지 전환 전에 폐기 여부를 확인한다.
- 빈 결과, 로딩, 오류/재시도를 구분한다. 표만 가로 스크롤되도록 작은 화면에 대응한다.

## 상담사 대시보드

`GET /consultant/dashboard`는 활성 상담사 본인의 현재 담당 고객을 기준으로 반환한다.

- `totalCustomers`: 상태별 DB 집계의 합계.
- `statusCounts`: 활성 `CUSTOMER_STATUS` 코드별 인원(0명 포함). 실제 데이터에만 남은 비활성/미등록 상태도 누락하지 않고 원래 코드명으로 추가한다.
- `recentCustomers`: `last_activity_at`이 있는 현재 담당 고객 중 최근 5명. 최근 상담일 내림차순, 동률은 고객 ID 내림차순. 같은 고객의 상담 여러 건은 고객 한 명으로 표시한다.

상태별 인원을 누르면 해당 상태가 적용된 고객 목록으로, 최근 고객의 상담 기록을 누르면 기존 상세 화면으로 이동한다. 고객이 없는 상태도 0명·빈 목록으로 표시한다.

## 요청 취소 오류

`getUsers`에서 취소 예외까지 `console.error`로 출력해 Next 개발 오류 화면이 나타났다. API의 중복 로깅을 제거하고 사용자 목록의 catch에서 `signal.aborted`와 Axios `isCancel`을 확인한다. 새 목록·대시보드 조회에도 동일하게 적용한다. 실제 서버 오류는 사용자에게 표시하고 재시도를 제공한다.

## 확인 범위

- TypeScript 및 변경 프론트 파일 ESLint 검사 통과.
- Next 프로덕션 빌드 통과. 외부 Google 폰트 다운로드가 필요한 기존 layout은 빌드 검증 중에만 시스템 폰트로 대체했고, 원본 파일을 복원했다. 폰트 관련 저장소 변경은 없다.
- Next 개발 모드: 느린 사용자 조회 중 화면 이동으로 취소를 재현, CanceledError 미표시·다음 조회 성공·실제 500 오류 표시와 재시도 확인.
- 브라우저 + 모의 API: 조합 필터의 요청값, 페이지 이동/초기화, 배정/해제 후 재조회, 상태·태그 수정 후 필터 반영과 마지막 페이지 보정, 대시보드 최근 5명/상태 링크/빈 결과/오류·재시도 확인.
- 1440/768/390px 화면에서 표의 내부 스크롤과 본문 넘침 여부 확인.
- 백엔드 회귀 테스트 추가: H2 기반 조건 조합·전화번호 서식·LIKE 이스케이프·본인 범위 강제·집계·최근 5명·재배정·빈 결과와 MVC 권한/파라미터 바인딩.
- Java 소스 문법 검사는 통과했다. 이 환경에서는 Gradle 배포본 다운로드가 `Network is unreachable`로 실패하여 백엔드 테스트 실행은 완료하지 못했다. 실제 DB에 연결한 검증과 모의 API 브라우저 검증은 구분한다.

이번 변경에는 DB 컬럼 추가나 마이그레이션이 없다.
